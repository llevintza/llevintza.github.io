Prometheus metrics for a Fastify API in one plugin

2026-11-026 min read#typescript#fastify#prometheussample post (mockup)

A new service needs the same four numbers on day one: request rate, error rate, latency and response size. @llevintza/fastify-prometheus-metrics collects them automatically, so a new Fastify API exposes them before it has any business logic.

Why a plugin

Hand-rolled metrics drift. One team names the histogram http_duration, another request_ms, and the dashboards stop lining up. A plugin fixes the names, labels and buckets in one place and lets each service override them on purpose.

Install and register

The package is published to GitHub Packages under the @llevintza scope.

shell
# Point the scope at GitHub Packages, then install
echo "@llevintza:registry=https://npm.pkg.github.com" >> ~/.npmrc
pnpm add @llevintza/fastify-prometheus-metrics

Registering it with no options is enough to get the default HTTP metrics at /metrics:

server.ts
import Fastify from 'fastify';
import fastifyPrometheusPlugin from '@llevintza/fastify-prometheus-metrics';

const fastify = Fastify();

await fastify.register(fastifyPrometheusPlugin, {
  excludeRoutes: ['/health', '/metrics'],
  defaultLabels: { service: 'my-api', version: '1.0.0' },
});

await fastify.listen({ port: 3000 });
// Metrics: http://localhost:3000/metrics

Choosing histogram buckets

The default latency buckets suit a typical JSON API. For a service with a long tail, pass your own, for example [1, 5, 15, 50, 100, 500, 1000, 5000] milliseconds, so the p99 lands inside a bucket instead of the overflow.

Release channels

Versions are cut automatically from the branch a change lands on:

BranchReleaseExampleUse case
mainStable1.0.0Production
release/*Beta1.1.0-beta.1Pre-release testing
feature/*Alpha1.1.0-alpha.2Feature development
The CloudWatch bridge is optional

Export to CloudWatch only where you already ship metrics to AWS. Everywhere else, including local development, the plugin serves a plain Prometheus endpoint.

Wrap-up

One register call gives a new service the metrics an on-call engineer reaches for first. The source, changelog and full option list are on GitHub.
